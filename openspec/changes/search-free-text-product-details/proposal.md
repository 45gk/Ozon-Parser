# Proposal

## Why

Сейчас поиск принимает только ссылку на выдачу Ozon. Пользователю приходится
вручную открывать Ozon, собирать URL категории или поиска и только потом
возвращаться в приложение. Кроме того, из выдачи сохраняются только поля
плитки: название, цена и рейтинг. Чтобы получить продавца, бренд, наличие,
описание и характеристики, каждую карточку приходится открывать отдельно.

Нужно, чтобы название товара было достаточным входом для поиска, а разбор
выдачи сразу сохранял подробные данные карточек.

## What Changes

- Поле ввода поиска принимает либо ссылку на `/category/...` или `/search/...`,
  либо свободный текст. Текст нормализуется в
  `https://www.ozon.ru/search/?text=...`.
- Существующий API `POST /api/searches` сохраняет совместимость: поле `url`
  по-прежнему обязательно, но теперь принимает и поисковую фразу.
- Добавляется флаг `parse_products` (по умолчанию `true`) и чекбокс в форме.
- При разборе выдачи парсер в той же браузерной сессии запрашивает
  `entrypoint-api` для каждой карточки и сохраняет подробности в новую таблицу
  `search_item_products`.
- Ошибка отдельной карточки не роняет весь поиск: она сохраняется в записи
  карточки, а выдача остаётся успешной.
- Детальная страница поиска показывает, сколько карточек разобрано, и
  раскрывает сохранённые детали по каждому товару.

## Capabilities

### New Capabilities

- `product-search`: поиск по ссылке или свободному тексту, разбор выдачи и
  автоматическое обогащение каждой позиции данными карточки.

### Modified Capabilities

Нет: в проекте ещё не было основных specs.

## Impact

- `ozon_parser/search.py`: нормализация запроса, флаг `include_products`,
  разбор карточек внутри браузерной сессии.
- `app/search_schemas.py`, `app/services/search_runner.py`: новый вход и
  сохранение подробностей.
- `app/db/models.py`: новая таблица `search_item_products`; существующие
  таблицы не меняются.
- `app/templates/search_index.html`, `search_detail.html`, `app/static/search.css`,
  `search.js`: свободный ввод, чекбокс, отображение деталей.
- `tests/test_search_parser.py`, `tests/test_web_app.py`: новые сценарии.
- Новых зависимостей нет. Схема создаётся через `Base.metadata.create_all`.
